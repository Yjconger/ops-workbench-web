## 2026-10-03 立项与骨架

- 起因：project-004（Codex CLI 版工作台）已验证 5 个 Skill 的口径与分析流程可行，但只有会在终端里跑 `codex` 的人能用，且每次分析都要等模型推理；
- 决策：把 project-004 的**业务口径与分析逻辑**重写成浏览器里的**确定性规则引擎**，做成可部署的静态网站。理由：
  1. 分析动作本质是固定的（看数据 → 读反馈 → 打标签 → 出策略），用规则引擎更快、更稳、可复现，且不消耗 token；
  2. 页面化之后运营同学不用装任何东西，打开网址就能用；
  3. 纯静态零构建，部署成本几乎为零。
- 产出：`src/index.html` + `style.css` + 六个 JS 模块（`data / engine / store / charts / llm / app`）。

## 2026-10-03 端到端冒烟测试与一个真 bug

- 新增 `src/tests/smoke.html` + `smoke.js`：在真实浏览器里点击九个页面、五类分析、三类台账写入和 11 种导出；
- **测出真 bug**：所有「下载 / 导出」按钮无效。原因是按钮写的是 `data-dl="check"`，而事件处理里只读了 `data-kind`，`buildReport(kind)` 拿到 `null` 直接返回，表现为"点了没反应、也不报错"；
- 修复：`var kind = t.getAttribute('data-kind') || t.getAttribute('data-dl');`
- 加固测试：不再只是"点一下不报错"，而是**劫持 `URL.createObjectURL` 与 `HTMLAnchorElement.prototype.click`**，记录每次导出的文件名与字节数，逐个断言（如 `晨检简报-2026-10-03.md 1201B`）。这样"点了没反应"这类静默失败会被直接抓住；
- 同时解决了无头 Chrome 里真实 `a.click()` 触发下载导致进程挂住的问题；
- 结果：**67 项全部通过**（`SUMMARY | total=67 failed=0`，页面标题 `SMOKE_OK`）。

## 2026-10-05 数据自动采集（取消手动上传）

- 需求：由产品后台每日自动采集上传各类数据与反馈文本，取消手动上传过程。
- 决策：不做「一次性上传」，做「采集层 + 自动同步」四段式 —— ① `scripts\collect-daily.ps1` 定时从后台拉数据 → ② `scripts\lib\manifest.cjs` 生成带 sha256 的 `manifest.json` → ③ 浏览器 `sync.js` 打开页面按 sha256 只下载新增 / 变更文件 → ④ 原「选择文件 / 粘贴文本」降级为「手动导入（兜底）」。
- 关键约束：Pages 发布的是 `src\`，所以**数据源目录必须放 `src\data\`**（不是仓库根 `data\`），否则线上访问不到。
- 命名约定唯一实现放在 `manifest.cjs` 的 `classify()`：`daily/YYYY-MM-DD-metrics.csv`、`daily/YYYY-MM-DD-feedback.txt`、`weekly/YYYY-Www-metrics.csv`、`users/YYYY-MM-users.csv`；占位符 `{date}` / `{week}` / `{month}`。采集器与演示数据生成器共用它，避免两套逻辑漂移。
- 新增文件：`config\sources.json`（5 个数据源模板，**全部 `enabled:false`**，待填后台地址与 Secret）、`.github\workflows\collect-daily.yml`（每天北京 01:00 = UTC 17:00）、`scripts\mock-backend.ps1`、`tests\fixtures\`、`src\tests\collect.e2e.ps1`、`src\tests\sync.test.cjs`、`src\assets\js\sync.js`、`src\data\`、`docs\03-数据自动采集.md`。
- UI：数据页改名「**数据源**」，加同步卡片（地址 / 自动开关 / 立即同步 / 检查更新 / 忘记已同步记录 / 日志），顶栏状态栏加「同步 正常·异常·未同步」；手动导入降级为「手动导入（兜底）」。
- 本轮修掉的真 bug：
  1. `sync.js` 重复 fetch —— reduce 里写成 `getJSON(...).then(...).then(() => fetchTimeout(...))`，导致每个文件下载两次；已改为单次 `fetchTimeout(base + f.path)`；
  2. UMD 的 CommonJS 分支不转发 root（`module.exports = factory()` 而非 `factory(root)`），`root` 为 `undefined`，Node 侧 `store.js` 的 `root.localStorage` 与 `save()` 报错刷屏；`store.js`、`sync.js` 已修（`charts.js` / `data.js` / `engine.js` / `llm.js` 目前不用 root，属同类隐患，暂未动）；
  3. `collect-daily.ps1` 的 `-DataRoot` / `-Config` 传**绝对路径**会被无条件拼到仓库根下（`Join-Path $RepoRoot 'C:\...'`）；已按 `IsPathRooted` 分支，并补 `$DataRel` 让 git 只 add 仓库内相对路径；
  4. `scripts\mock-backend.ps1` 原先用 `System.Net.HttpListener`，它依赖 http.sys 的 URL ACL，**受限环境 / 普通用户 `Start()` 直接报「句柄无效」**；改用纯 `TcpListener` 自己实现最小 HTTP/1.1 响应，无需管理员权限。

## 2026-10-05 手动导入保留 + 手动数据优先级最高

- 需求：保留手动上传数据功能，且与自动上传的数据相比，**手动数据为最高优先级**。
- 问题：原来的写法是「后写覆盖」——`replaceByKey` 无条件替换同 key 记录。手动导入后打开页面触发一次自动同步，手动词的值就被后台值冲掉了。
- 方案：给数据加**来源等级 + 两层保护**。
  - 记录级：每条数据带 `_src`（`manual` / `auto` / `sample`）；`SRC_LEVEL = { manual: 2, auto: 1, sample: 1 }`；`mergeByKey()` 里只有 `srcLevel(新) >= srcLevel(旧)` 才允许覆盖。这一层保证**即使拿不到文件名**（粘贴文本、用户行为行无日期字段）手动记录也不会被冲掉。
  - 文件级：`state.locks = { daily:{}, weekly:{}, users:{}, feedback:{} }`，手动导入把 `日期/周期` 记进去；`sync.js` 的 `plan()` 把被锁文件挪进 `locked` 桶，**不下载不覆盖**，`run()` 结果里回报 `locked` 数量与「N 个文件被手动导入的数据锁定，未覆盖」。
- 解除入口：「数据源」页 `lockBar()` 提示条（列出被占用的日期 + 「解除手动优先」按钮）。`S.unlockManual()` 清 `locks`、把 `manual` 记录降级为 `auto`，**并清空 `sync.files` 哈希缓存**。
- 踩坑（关键）：解锁时**必须清哈希缓存**。这些文件当初已被自动同步过一次、sha 已进 `c.files`，只是被文件锁挡掉；不清缓存下一次同步会判定「无变化」而拒绝下载，手动值就永远盖不回去了。（测试 `解锁同时清空哈希缓存` 这条断言就是为它写的。）
- 顺带：`store.js` 抽出 `hydrate()` 统一补齐老工作区缺的 `locks` / `sync` 字段；`loadSample()` 明确用 `sample` 级（既不覆盖手动数据，也会被自动数据覆盖）；`clearData()` 同时清对应 `locks`。
- 文案：数据页「手动导入（兜底）」→「手动导入（优先级最高）」，页面开头说明手动优先；导入成功 toast 追加「（手动数据优先，自动同步不会覆盖）」。
- 验证：`node src\tests\sync.test.cjs` **60/60**（新增 22 项：manual 标记、锁定、同步跳过、`locked=1`、未覆盖手动值、解锁、重下、自动值恢复）；`node src\tests\engine.test.cjs` **48/48**；无头 Chrome `src\tests\smoke.html` **78/78**（新增 11 项：提示条出现/列出日期/解锁按钮/解除后消失）。
- 文档：`docs\03-数据自动采集.md` 新增「八、手动导入优先规则（手动 > 自动）」（原八/九/十顺延为九/十/十一）；`docs\01-使用手册.md` 的 2.0.1 与 3.9 补优先规则；`README.md` 特性与第六节同步更新。
