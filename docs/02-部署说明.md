# 部署说明 · 把工作台变成公网网址

> 网站本体在 `src\` 目录，纯静态、零构建。**发布目录一律填 `src`**，不需要任何 build 命令。
>
> 只是想**最快拿到网址**？直接跳到「方式零」，全程网页点选，不用装 Git。

先确认两件事：

1. `src\index.html` 用的是**相对路径**（`assets/css/style.css`），所以部署在子路径（如 `https://名字.github.io/仓库名/`）也能正常显示；
2. 没有后端、没有数据库、没有接口调用，所以任何静态托管都能跑，也不需要配置环境变量。

---

## 方式零：GitHub 网页上传（最快，5 分钟，不用装任何工具）

> 没有 Git 命令、不想配 Token，就用这条。全程在网页上点。

1. 打开 <https://github.com/new>，创建一个仓库：
   - **Repository name**：`ops-workbench-web`（随便起）
   - 选 **Public**（私有仓库的 Pages 要付费账号）
   - **不要**勾 "Add a README file"、".gitignore"、"license" —— 保持**空仓库**，否则后面会冲突
   - 点 **Create repository**
2. 在新仓库页面点 **uploading an existing file**（或 Add file → Upload files）；
3. 打开本机文件夹 `E:\workplace\projects\project-005-运营工作台Web版\src`，把里面的
   **`index.html`、`favicon.svg`、`assets` 文件夹** 一起选中，拖进网页的上传区；
   - ⚠️ 拖的是 `src` **里面的内容**，不是 `src` 这个文件夹本身。上传完仓库根目录应该直接能看到 `index.html`
4. 下方 Commit changes 填一句说明（如 `first deploy`），点 **Commit changes**；
5. 点仓库的 **Settings → Pages**：
   - **Source** 选 `Deploy from a branch`
   - **Branch** 选 `main`，目录选 `/(root)`
   - 点 **Save**
6. 等 1–2 分钟，刷新这个 Pages 页面，顶部会出现网址：

   ```text
   https://<你的用户名>.github.io/ops-workbench-web/
   ```

7. 手机上也打开一次，确认样式正常、能点「载入示例数据」。

**以后更新网站**：回到仓库 → Add file → Upload files → 重新拖一次覆盖同名文件 → Commit，1 分钟后线上自动更新。

**小提示**：如果页面样式丢失，多半是第 3 步只传了 `index.html` 没传 `assets` 文件夹。仓库根目录必须同时有 `index.html` 和 `assets\`。

## 方式一：GitHub Pages（免费，适合长期维护）

**准备**：一个 GitHub 账号 + Git。

1. 在本项目文件夹里初始化仓库（**把本文件夹当作仓库根目录**）：

   ```powershell
   cd "E:\workplace\projects\project-005-运营工作台Web版"
   git init -b main
   git add .
   git commit -m "feat: 运营分析工作台 Web 版"
   ```

2. 在 GitHub 上新建一个仓库（公开或私有都行），然后推送：

   ```powershell
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```

3. 打开仓库 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**；
4. 仓库里已经带好 `.github\workflows\deploy-pages.yml`，推送后会自动把 `src\` 发布成网站；
5. 等 Actions 跑完（约 1 分钟），网址是：

   ```text
   https://<你的用户名>.github.io/<仓库名>/
   ```

> 已经带了 `src\.nojekyll`，不会再被 Jekyll 处理。以后每次 `git push` 都会自动重新部署。

## 方式二：Cloudflare Pages（免费，国内访问通常比 GitHub Pages 稳）

1. 打开 <https://dash.cloudflare.com/> → **Workers & Pages → Create → Pages → Connect to Git**；
2. 选中刚才的仓库；
3. 构建配置这样填：
   - **Framework preset**：`None`
   - **Build command**：留空
   - **Build output directory**：`src`
4. 点 **Save and Deploy**，1 分钟后拿到 `https://<项目名>.pages.dev`。

> 也可以不用 Git：**Create → Pages → Upload assets**，直接把 `src` 文件夹里的内容拖进去。

---

## 方式三：Netlify 拖拽上传（最快，5 分钟出网址）

1. 打开 <https://app.netlify.com/drop>；
2. 把 `src` 文件夹**整个拖进**网页；
3. 立刻得到一个 `https://<随机名>.netlify.app` 网址，可直接打开使用；
4. 想固定网址、接自己的域名、每次更新自动部署：注册登录后 **Site configuration → Build & deploy** 关联 Git 仓库，发布目录填 `src`（仓库里已有 `netlify.toml`，会自动识别）。

---

## 方式四：Vercel

1. <https://vercel.com/new> → 导入仓库；
2. Framework Preset 选 `Other`，**Build Command** 留空，**Output Directory** 填 `src`；
3. Deploy。仓库里已有 `vercel.json`，正常情况下会自动按上述配置识别。

## 部署后自检清单

在手机上再打开一次，确认：

- [ ] 首页能正常显示，样式正常（没有裸露的 HTML）；
- [ ] 点左下角「载入示例数据」，概览页数字从 0 变成 14 天 / 24 条 / 12 位；
- [ ] 每日晨检页有简报和待办，指标表有红色「异常」标签；
- [ ] 反馈分析页有环形图；
- [ ] 指标分析页有折线图，点「导出 HTML 看板」能下载文件；
- [ ] 台账页「写入台账」后表格出现行，导出 CSV 能用 Excel 打开且中文不乱码；
- [ ] 刷新页面后数据还在（说明 `localStorage` 正常）。

如需自动化自检：部署完后打开 `https://<你的网址>/tests/smoke.html`，页面标题变成 `SMOKE_OK` 就是 67 项全通过。

> `tests\` 是开发自检页，不会影响正常使用；不想公开可以部署前删掉 `src\tests\`。

## 常见部署问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 页面 404 / 空白 | 发布目录填错了。填的是仓库根目录而不是 `src`；或拖拽时拖了项目文件夹而不是 `src` 里的内容 |
| 样式丢失、只有文字 | `assets\` 没跟着上传。确认发布目录里同时有 `index.html`、`assets\`、`favicon.svg` |
| 中文乱码 | 文件被编辑器改成了 GBK。所有文件应存为 UTF-8（本仓库默认带 BOM 的 UTF-8） |
| 数据刷新就没了 | 部署成功了吗？`file://` 本地打开可能被浏览器限制 `localStorage`，用网址访问即可 |
| AI 解读按钮报错 | 没填 Key 或填错。见 `01-使用手册.md` 第六节；不填也能正常分析 |

## 关于数据安全（重要）

这是**纯前端应用**：数据只存在每个访问者自己的浏览器里，服务器上什么都没有。

- 好处：不用怕数据泄露到服务器，也不用交服务器费用；
- 代价：**每个访问者的数据是各自独立的**，你打开看到的是你自己的数据，同事打开看到的是他的；
- 因此在公网部署时请记住：不要把公司敏感数据填进公网站点，除非你清楚它只留在你自己浏览器里；
- 需要多人共用一份数据的话，那要走"带后端"的方案（本版不含），或各自用「导出工作区 JSON」互相传递。
