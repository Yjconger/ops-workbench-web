# 数据自动采集 · 取消手动上传

> 一句话：**每天由产品后台定时采集数据，自动提交到仓库；打开网页时自动同步进工作区，你什么都不用做。**

---

## 一、为什么不用再手动上传了（手动入口保留，且优先级最高）

原先的流程是「后台导出 CSV → 存到本地 → 打开网页 → 点选择文件 → 逐个导入」，每天重复一遍。

现在拆成四段，中间那两段机器自己跑：

```text
① 产品后台                ② 采集器                     ③ 数据源目录              ④ 浏览器
开放接口 / 定时导出    →   scripts/collect-daily.ps1  →   src/data/            →   打开页面自动同步
对象存储 / 本机导出目录     按配置拉取 + 规范化口径         CSV + manifest.json      按 sha256 只取新增/变更
（每天定时触发）           幂等：数据没变就不提交          （随站点一起发布）        解析后写入工作区
```

- **① 采集**：`scripts/collect-daily.ps1` 按 `config/sources.json` 拉取数据；
- **② 校验**：`scripts/lib/manifest.cjs` 给每个文件算 sha256，生成 `manifest.json`（采集器和演示数据生成器共用同一个实现，避免两套逻辑漂移）；
- **③ 感知**：浏览器打开页面时拉 `manifest.json`，和本地已同步记录比对，**只下载新增 / 变更的文件**；
- **④ 兜底（且优先级最高）**：原来的「选择文件 / 粘贴文本」全部保留，改称「手动导入」；手动导入的数据**优先级高于自动同步**，不会被覆盖（详见第八节）。

---

## 二、关键决策：数据必须放在 `src/data/`

工作台通过 GitHub Pages 发布，而 `.github/workflows/deploy-pages.yml` 发布的是 **`src/` 子目录**。

所以：

- 数据源目录 = **`src/data/`**（不是仓库根的 `data/`），否则线上访问不到；
- 网站里读的是**同站相对路径** `data/manifest.json`，跟随 Pages 子路径（`https://用户.github.io/ops-workbench-web/data/manifest.json`）；
- `src/data/` 里的文件会随站点一起公开（见第七节「安全」）。

---

## 三、命名约定（唯一规则）

`manifest.cjs` 的 `classify()` 是这套规则**唯一**的实现，采集器、演示数据生成器、浏览器同步都依赖它。

| 目录 | 文件名格式 | 类型 | 例子 |
| --- | --- | --- | --- |
| `data/daily/` | `YYYY-MM-DD-metrics.csv` | 日指标 | `2026-10-04-metrics.csv` |
| `data/daily/` | `YYYY-MM-DD-feedback.txt` | 日反馈 | `2026-10-04-feedback.txt` |
| `data/weekly/` | `YYYY-Www-metrics.csv` | 周指标 | `2026-W40-metrics.csv` |
| `data/users/` | `YYYY-MM-users.csv` | 用户行为 | `2026-10-users.csv` |

**不符合命名的文件会被直接忽略**（不进清单、不会被同步）。日期从文件名解析，所以文件名就是数据日期。

配置里的日期占位符：

| 占位符 | 含义 | 例子 |
| --- | --- | --- |
| `{date}` | 采集日 `yyyy-MM-dd` | `2026-10-04` |
| `{week}` | ISO 周（周一起算，跨年按 ISO） | `2026-W40` |
| `{month}` | 采集月 `yyyy-MM` | `2026-10` |

## 四、数据源配置 `config/sources.json`

结构：

```jsonc
{
  "version": 1,
  "source": "产品后台（示例配置，尚未启用）",   // 会写进 manifest.json 的 source 字段，显示在「数据源」页
  "sources": [ /* 一个数据源一项 */ ]
}
```

### 三种适配器

| `type` | 用途 | 关键字段 |
| --- | --- | --- |
| `http-json` | 后台开放接口，返回 JSON 数组 | `url`、`rowsPath`、`fields` |
| `http-file` | 后台/对象存储的定时导出文件（CSV/TXT） | `url`、`saveAs` |
| `local-export` | 本机导出目录（员工机计划任务） | `path`、`saveAs` |

### 4.1 日指标（http-json）

```jsonc
{
  "name": "日指标 · 后台开放接口",
  "enabled": true,
  "type": "http-json",
  "kind": "daily",
  "url": "https://api.your-company.com/ops/metrics?date={date}",
  "auth": { "scheme": "bearer", "tokenEnv": "OPS_API_TOKEN" },
  "rowsPath": "data.list",
  "fields": { "metric": "metric_name", "value": "value", "compare": "prev_value", "basis": "compare_basis" }
}
```

假设接口返回：

```json
{ "code": 0, "data": { "list": [ { "metric_name": "日活跃用户数", "value": 12480, "prev_value": 13010, "compare_basis": "昨日" } ] } }
```

`rowsPath` = `data.list` 定位到数组；`fields` 把后台字段名映射成工作台口径：

| `fields` 键 | 对应列 | 说明 |
| --- | --- | --- |
| `metric` | 指标 | 必填，要和「口径设置」里的指标名一致 |
| `value` | 数值 | 必填 |
| `compare` | 对比值 | 可选 |
| `basis` | 对比口径 | 可选，缺省写「昨日」 |

`rowsPath` / `fields` 都支持 `a.b.c` 点号取值，也支持数组下标（如 `data.0.list`）。

### 4.2 用户反馈（http-json）

```jsonc
{
  "name": "用户反馈 · 后台开放接口",
  "enabled": true,
  "type": "http-json",
  "kind": "feedback",
  "url": "https://api.your-company.com/ops/feedback?date={date}",
  "auth": { "scheme": "apikey", "header": "X-API-Key", "tokenEnv": "OPS_API_KEY" },
  "rowsPath": "data.list",
  "fields": { "time": "created_at", "channel": "source", "userId": "uid", "content": "text" }
}
```

会被拼成工作台认的 `时间 | 渠道 | 用户ID | 内容` 一行一条：

| `fields` 键 | 对应位置 |
| --- | --- |
| `time` | 时间 |
| `channel` | 渠道 |
| `userId` | 用户ID |
| `content` | 内容 |

### 4.3 周指标 / 用户行为（http-json）

```jsonc
{ "kind": "weekly", "url": "...?week={week}", "rowsPath": "data.list",
  "fields": { "period": "period", "metric": "metric_name", "value": "value", "mom": "mom", "yoy": "yoy" },
  "period": "2026-W40" }
```

```jsonc
{ "kind": "users", "url": "...?month={month}", "rowsPath": "data.list",
  "fields": { "id": "uid", "regDate": "reg_date", "lastActive": "last_active", "orders": "orders",
              "amount": "amount", "fbCount": "fb_count", "lastFbDate": "last_fb_date", "channel": "channel", "note": "note" },
  "period": "2026-10" }
```

> `period` 是**落盘文件名用的周期标识**（周：`2026-W40`；月：`2026-10`），不是接口字段。

### 4.4 后台只给导出文件（http-file）

```jsonc
{
  "name": "用户行为 · 后台定时导出到对象存储",
  "enabled": true,
  "type": "http-file",
  "kind": "users",
  "url": "https://cdn.your-company.com/ops/users/{month}-users.csv",
  "saveAs": "{month}-users.csv"
}
```

文件内容按工作台口径直接落盘（不再做字段映射）。`saveAs` 不写就从 URL 末段取文件名 —— 但那样往往不符合第三节的命名约定，**建议显式写 `saveAs`**。

### 4.5 后台导出到本机目录（local-export）

```jsonc
{
  "name": "本机后台导出目录",
  "enabled": true,
  "type": "local-export",
  "kind": "daily",
  "path": "D:\\ops-export\\{date}-metrics.csv",
  "saveAs": "{date}-metrics.csv"
}
```

适合「后台只能手动点导出、但能设置成自动导到某个文件夹」的情况。

## 五、凭据怎么给（不要写进仓库）

`auth.tokenEnv` 指向的是**环境变量名**，配置里永远不出现密钥本身。

| 运行方式 | 怎么给凭据 |
| --- | --- |
| GitHub Actions | 仓库 **Settings → Secrets and variables → Actions → New repository secret**，名字填 `OPS_API_TOKEN` / `OPS_API_KEY` |
| 本机计划任务 | 在 `.ps1` 包装脚本里 `$env:OPS_API_TOKEN = '...'`，或设成用户级环境变量 |

三种 `scheme`：

| `scheme` | 发出去的请求头 | 额外字段 |
| --- | --- | --- |
| `bearer` | `Authorization: Bearer <token>` | — |
| `apikey` | `<header>: <token>` | `header`（如 `X-API-Key`） |
| `basic` | `Authorization: Basic base64(<token>)` | — |

> 环境变量没设时**不会报错**，只是不带鉴权头发请求 —— 接口通常会返回 401，采集器会明确标 `[failed]`。

## 六、怎么触发

### 6.1 GitHub Actions 定时（推荐，电脑关机也会跑）

仓库里已有 `.github/workflows/collect-daily.yml`：

- 触发时间：**北京时间每天 01:00**（`cron: '0 17 * * *'`，UTC 17:00）；
- 也可以手动跑：仓库 **Actions → 每日数据采集 → Run workflow**，可填一个采集日期（留空 = 昨天）；
- 跑完会 `git commit` + `push`，Pages 自动重新发布，随后访问者打开页面即自动同步；
- 采集失败不会让工作流"红"到无法定位：摘要里会列出各数据源结果。

采集日期默认取**昨天**（凌晨跑，采的是刚过完的一天）。

### 6.2 本机计划任务（后台只在内网可访问时）

```powershell
# 每天 09:30 采集昨天的数据（按需改时间 / 日期）
schtasks /Create /TN "OpsWorkbench-采集" /SC DAILY /ST 09:30 ^
  /TR "pwsh -NoProfile -File \"E:\workplace\projects\project-005-运营工作台Web版\scripts\collect-daily.ps1\""
```

### 6.3 手动跑一次

```powershell
cd "E:\workplace\projects\project-005-运营工作台Web版"
pwsh -NoProfile -File scripts\collect-daily.ps1                    # 采昨天
pwsh -NoProfile -File scripts\collect-daily.ps1 -Date 2026-10-04   # 采指定日期
pwsh -NoProfile -File scripts\collect-daily.ps1 -DryRun            # 只校验，不写文件不提交
pwsh -NoProfile -File scripts\collect-daily.ps1 -NoCommit          # 写文件但不提交（本地调试）
```

参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-Config` | `config/sources.json` | 数据源配置（可传绝对路径） |
| `-DataRoot` | `src/data` | 数据源目录（可传绝对路径，测试用临时目录） |
| `-Date` | 昨天 | 采集日期 `yyyy-MM-dd` |
| `-DryRun` | — | 只拉取不落盘不提交 |
| `-NoCommit` | — | 落盘但不 git 提交 |

**幂等**：同一份数据重复采集，文件内容不变就不会重写，也不会产生新提交 —— 所以定时任务多跑几次没有副作用。

## 七、浏览器端怎么工作（「数据源」页）

打开页面时会自动做一次同步（可在「数据源」页关掉「打开页面自动同步」）。

| 控件 | 作用 |
| --- | --- |
| 同步地址 | 默认 `data/`（同站）。也可填后台 / 对象存储的 `https://…` 前缀（对方需允许 CORS） |
| 打开页面自动同步 | 每次打开页面拉一次清单并同步 |
| 立即同步 | 手动拉一次清单并下载新增 / 变更文件 |
| 检查更新 | 只比对不下载，先看有多少要更新 |
| 忘记已同步记录 | 清空本地哈希记录，下次同步会重新下载全部（数据异常时用来「重新拉一遍」） |
| 同步日志 | 最近 20 次同步的时间 / 结果 / 新增文件数 / 记录数 |

同步按 **sha256** 判断：文件内容没变就不重复下载；**换同步地址视为换了一份数据**，会自动清空哈希记录。

同步失败**不会**抛异常、也不会影响工作台其他功能 —— 结果结构化成一条日志（顶栏状态栏显示「同步 正常 / 异常 / 未同步」），离线时照常用手动导入。

## 八、手动导入优先规则（手动 > 自动）

自动同步不是唯一入口：**原来的「选择文件 / 粘贴文本」全部保留**，而且优先级最高。

### 8.1 优先级
| 来源 | 级别 | 行为 |
| --- | --- | --- |
| `manual` 手动导入（选择文件 / 粘贴文本） | **2（最高）** | 写入时把 日期/周期 记入 `locks`，自动同步跳过它；同 key 的记录不会被 `auto` 覆盖 |
| `auto` 自动同步（本工作流） | 1 | 只在目标 key 未被手动锁定时覆盖 |
| `sample` 载入示例数据 | 1 | 同 auto；它也不会覆盖手动数据 |

判优先级有两层，缺一不可：

1. **文件锁（`state.locks`）**：`daily/2026-10-04` 被手动导入后，`2026-10-04-metrics.csv` 整个文件在 `plan()` 阶段就被挪进 `locked` 桶，**不下载、不覆盖**，同步结果里写明「N 个文件被手动导入的数据锁定，未覆盖」；
2. **记录级来源标记（`_src`）**：每条记录带 `_src`，合并时 `srcLevel(旧) > srcLevel(新)` 就保留旧值。这样即使拿不到文件名（粘贴文本、用户行为行里没有日期字段），标为 `manual` 的记录同样不会被自动数据冲掉。

### 8.2 解除手动优先
「数据源」页的提示条上有 **解除手动优先**：

- 清空对应 kind 的 `locks`，并把 `_src='manual'` 的记录降级为 `auto`；
- **同时清空 `sync.files` 哈希缓存** —— 这些文件当初可能已经被自动同步过、只是被锁挡掉了；不清缓存的话下一次同步会判定「无变化」而拒绝下载，自动数据就永远盖不回来；
- 解除后立刻重新同步一次，这些日期就回到「以自动数据为准」。

### 8.3 为什么不按记录粒度锁定文件
文件是同步的最小单位（一个 CSV 就是一天 / 一周 / 一月）。按日期整体锁定语义最直观：**「这一天我手工定了，后台先别动」**。后台之后对同一天的修订要进来，点一次解除即可。

```powershell

pwsh -NoProfile -File scripts\mock-backend.ps1 -Port 8111 -Root tests\fixtures\backend

# 另一个终端：按测试配置采一次
pwsh -NoProfile -File scripts\collect-daily.ps1 -Config tests\fixtures\sources.test.json -DataRoot .\tmp-data -Date 2026-10-04 -NoCommit
```

一键跑完整端到端测试（自己起 Mock 后台、跑完自己回收）：

```powershell
pwsh -NoProfile -File src\tests\collect.e2e.ps1
```

预期 `SUMMARY | pass=21 fail=0`：字段映射正确、清单哈希与文件一致、第二次采集全 `unchanged`（幂等）、`-DryRun` 不落盘。

其他自检：

```powershell
node src\tests\sync.test.cjs     # 清单 / 一致性 / 同步器 / 幂等 / 手动优先：60 项
```

浏览器里的「真实 HTTP」集成检查（会清空本浏览器工作区数据，只在自检时打开）：

## 十、安全（重要，部署前务必看）

- **数据会公开**：`src/data/` 随站点一起发布。仓库是 public 时，**任何人都能下载这些 CSV / 反馈原文**。真实用户反馈、订单金额等敏感数据请勿直接进公开仓库 —— 私有仓库 + 未公开的部署方式才能放。
- **反馈文本里的人名 / 手机号 / 订单号**建议在采集侧先脱敏再落盘。
- **不要提交密钥**：配置里只写环境变量名（`tokenEnv`），密钥放 GitHub Secrets 或本机环境变量。
- 数据方向是**只读**的：网页只从数据源目录下载，从不回传任何数据。

## 十一、排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 采集器输出「没有启用任何数据源」 | `config/sources.json` 里 `enabled` 都是 `false` —— 这是初始状态，填好地址改为 `true` |
| 某数据源 `[failed]` | 看后面的错误：401/403 = 凭据没设或过期；404 = 地址 / 占位符不对；超时 = 网络或后台不通 |
| 文件采下来了但「数据源」页没同步到 | 文件名不符合第三节命名约定（会被忽略）；或 Actions 还没跑完；或该文件在 `manifest.json` 生成之前就放进去了 |
| 线上 404 打不开 `data/manifest.json` | 数据放错目录了 —— 必须是 `src/data/`（Pages 发布的是 `src/`） |
| 浏览器报 CORS 错误 | 同步地址指到了别的域名，对方没开 CORS，改用同站 `data/` |
| 同步说「已是最新」但数据明显是旧的 | 采集器没真正写新文件（看 Actions 日志）；或换了同步地址导致记录被清空后误判 —— 点一次「立即同步」 |
| 采到一半文件是空的 | 后台接口返回了空数组。`rowsPath` 定位不对时会直接报错，但返回空数组是合法响应，会生成只有表头的文件 |
