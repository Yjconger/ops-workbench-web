# 使用手册 · 运营分析工作台 Web 版

> 目标：不懂技术也能用。照着做，第一次 5 分钟能跑出结果。

## 一、五分钟上手

1. 打开网页（本地启动见 `README.md` 第五节，或直接用部署好的网址）；
2. 点左下角 **载入示例数据** —— 会灌入 14 天日指标、8 周周指标、12 位用户、24 条反馈；
3. 左侧依次点一遍：**概览 → 每日晨检 → 反馈分析 → 指标分析 → 用户分层 → 整合分析**；
4. 每个页面右上角都有「写入台账」「下载…」按钮，跑完一轮后去 **台账** 页看留痕；
5. 熟悉后如果是**自己试玩**：点 **数据源** 页 → 每个卡片右侧「清空」，再导入自己的数据；
6. 如果是**在工作里用**：什么都不用导 —— 后台数据每天自动采集，打开页面就自动同步进来（见 2.0）。

## 二、数据怎么准备

### 2.0 正常情况下：你不需要准备（自动采集）

产品后台的数据每天由采集器自动拉取、提交到仓库，**打开页面时会自动同步进工作区**（顶栏状态栏会显示「同步 正常」）。

- 想确认有没有新数据：**数据源** 页 → 「检查更新」；想立刻拉一次：**立即同步**；
- 不想每次打开都同步：**数据源** 页 → 关掉「打开页面自动同步」；
- 同步记录看得见：**数据源** 页 → 「同步日志」（最近 20 次）；数据看着不对可以「忘记已同步记录」，下次会重新下载全部；
- 数据源不通（内网 / 断网）也不影响用：照下面的方式手动导入即可。

配置后台地址、鉴权方式、定时任务等，见 `docs\03-数据自动采集.md`。

### 2.0.1 兜底：手动导入

同步不可用时，网页支持两种导入方式：**选择文件**（可多选、可拖一批）和**粘贴文本**（来不及存文件时用）。

### 2.1 每日指标（日指标 CSV）

- 文件名建议 `YYYY-MM-DD-metrics.csv`（程序会从文件名里取日期；不带日期也行，导入时用当天）；
- 表头必须含 **指标** 和 **数值** 两列，**对比值**、**对比口径** 可选：

```csv
指标,数值,对比值,对比口径
日活跃用户数,12840,13100,环比昨日
新增注册用户,326,410,环比昨日
付费订单数,182,196,环比昨日
支付成功率(%),93.2,97.1,环比昨日
订单转化率(%),2.78,3.12,环比昨日
退款率(%),3.2,1.8,环比昨日
接口平均响应时长(ms),2050,1380,环比昨日
核心功能使用率(%),40.3,42.6,环比昨日
次日留存率(%),36.1,37.0,环比昨日
负面反馈数,14,6,环比昨日
```

> 指标名称要和「口径设置」页里的名称对得上（默认 11 项，见第四节）。对不上的指标会被列出来但不参与判定。

### 2.2 用户反馈（TXT）

一行一条，用 `|` 分隔四个字段：

```text
09:20 | 应用商店 | U10231 | 升级后支付一直失败，试了三次都不行，钱还扣了
10:05 | 客服 | U10876 | 导出报表要等好久，等到怀疑人生
# 这一行以 # 开头，是注释，不会被读入
```

- 字段顺序：`时间 | 渠道 | 用户ID | 内容`；
- 只有一行普通文字（不含 `|`）也能导入，整行当内容；
- 建议文件名 `YYYY-MM-DD-feedback.txt`，日期同样从文件名取。

### 2.3 周指标（CSV）

```csv
周,指标,数值,环比,同比
2026-W40,周活跃用户数,48200,2.1%,8.4%
2026-W40,周付费订单数,1120,-3.2%,5.1%
```

### 2.4 用户行为（CSV）

```csv
用户ID,注册日期,最近活跃日期,累计订单数,累计付费金额,反馈次数,最近反馈日期,渠道,备注
U10231,2025-11-03,2026-10-03,12,3480,6,2026-10-03,应用商店,
U10455,2026-09-28,2026-10-03,0,0,2,2026-10-02,自然流量,新注册
```

- 用户ID 唯一；缺数据留空，**不要填 0**（填 0 会被当成"真的没有"）；
- 「备注」可以写「回流」「已流失」等，打标签时会参考。

### 2.5 编码与格式坑

- 统一存成 **UTF-8**：Excel → 另存为 → **CSV UTF-8（逗号分隔）**；
- 数字列不要写 `￥`、`,`、`%` 等符号（`93.2%` 请写 `93.2`）；
- 同一份文件重复导入不会重复计：按 **日期 + 指标**（用户按 用户ID、反馈按 日期 + 内容）覆盖。

## 三、五个页面怎么用

### 3.1 概览

看四件事：数据齐不齐（缺哪个会提示去补）、最新数据日期、最近跑过哪几次分析、以及四个场景的快速入口。

### 3.2 每日晨检（约 30 秒）

- 顶部选日期 → 只扫**当天**；
- 输出：**≤200 字简报**（红字标注越界指标和集中反馈）+ **最多 3 条今日待办**（每条带依据和时间）；
- 「当日指标状态」表里，状态列是 `异常 / 需关注 / 正常`，最后一列是近 14 天迷你走势；
- 想要留痕就点 **写入台账**；要发给同事就点 **下载简报 Markdown**。

### 3.3 反馈分析（1–2 分钟）

输入全部反馈（或按情感筛选），输出四块：

1. **情感分布**环形图 + 负面占比；
2. **高频问题 Top5**：问题类型、提及次数、涉及用户数、代表原话；
3. **需求建议**：带 P0/P1/P2 优先级，每条有「依据」和「建议动作」；
4. **反馈明细**：逐条标注情感、类型、判定依据词。

可点 **导出明细 CSV** 拿去 Excel 继续做透视。

### 3.4 指标分析（1–2 分钟）

- 粒度切换 **日 / 周**（周数据来自周指标 CSV）；
- 输出：核心指标概览表（数值、对比、变化、状态、近 14 天走势）、**异常标注**卡片、**归因假设**（每条异常给 2–3 个可验证的假设）、趋势图；
- **导出 HTML 看板** 会生成一个自带样式的单文件 HTML，可以直接发给别人或贴进文档。

### 3.5 用户分层（1–2 分钟）

按三个维度给每位用户打标签：

- **生命周期**：新用户 / 活跃 / 沉默 / 流失风险 / 已流失 / 回流；
- **价值**：高价值 / 中价值 / 低价值 / 未付费；
- **反馈行为**：高频反馈 / 问题反馈 / 正面反馈 / 无反馈；

输出标签清单 + **建议动作**（如"高价值 + 流失风险 → 本周一对一触达"）。第二次打标时会对比上次台账，标出**迁移**（如 沉默 → 回流）。

### 3.6 整合分析（2–3 分钟）

把上面四块的产出交叉验证，输出：

- **本期核心发现**（3–5 条）；
- **交叉验证表**：每条反馈主题 vs 对应指标 → ✅ 印证 / ⚠️ 背离 / ❓ 无法判断；
- **产品策略建议**（3–5 条，每条都写清"验收指标"，可验证）；
- **下周监控重点**（3–5 项）+ **补数清单**（哪些数据缺口让你无法判断，先去补）。

### 3.7 台账

三个台账：`ledger.csv`（分析结论）、`metrics-ledger.csv`（指标与异常）、`tag-ledger.csv`（用户标签）。
支持搜索、删单条、清空、**导出 CSV**（带 BOM，Excel 直接打开不乱码）。

### 3.8 口径设置

不动代码就能改业务口径，改完点 **保存口径**：

- **指标口径**：方向（越高越好 / 越低越好）、正常阈值、关注阈值、环比关注/异常百分比；
- **反馈词表**：负面词、正面词、负面句式、六类问题的关键词；
- **标签阈值**：生命周期与价值的判定标准（如"高价值 = 累计付费 ≥ X 元"）；
- **动作矩阵**：不同标签组合建议做什么。

> 改错了点 **恢复默认** 即可。改好的口径可以 **导出口径 JSON** 备份，换电脑时导入。

### 3.9 数据源（自动同步）

| 控件 | 作用 |
| --- | --- |
| 同步地址 | 默认 `data/`（同站）。也可填后台 / 对象存储的 `https://…` 前缀（对方需允许 CORS） |
| 打开页面自动同步 | 每次打开页面拉一次清单并同步 |
| 立即同步 | 手动拉一次清单并下载新增 / 变更文件 |
| 检查更新 | 只比对不下载，先看有多少要更新 |
| 忘记已同步记录 | 清空本地哈希记录，下次同步会重新下载全部（数据异常时用来「重新拉一遍」） |
| 同步日志 | 最近 20 次同步的时间 / 结果 / 新增文件数 / 记录数 |

同步按文件内容哈希（sha256）判断：内容没变就不重复下载；**换同步地址视为换了一份数据**，会自动清空记录。
同步失败不会影响其他功能，顶栏状态栏会标成「同步 异常」，照常用手动导入兜底。

## 四、默认口径（内置，可在口径设置页改）

| 指标 | 方向 | 正常 | 关注 |
| --- | --- | --- | --- |
| 日活跃用户数 | 越高越好 | 环比 ≥ -10% | ≥ -20% |
| 新增注册用户 | 越高越好 | 环比 ≥ -15% | ≥ -30% |
| 付费订单数 | 越高越好 | 环比 ≥ -10% | ≥ -20% |
| 支付成功率(%) | 越高越好 | ≥ 97 | ≥ 95 |
| 订单转化率(%) | 越高越好 | ≥ 3.0 | ≥ 2.5 |
| 退款率(%) | 越低越好 | ≤ 2.0 | ≤ 3.0 |
| 接口平均响应时长(ms) | 越低越好 | ≤ 1500 | ≤ 2000 |
| 核心功能使用率(%) | 越高越好 | ≥ 40 | ≥ 35 |
| 次日留存率(%) | 越高越好 | ≥ 35 | ≥ 30 |
| 负面反馈数 | 越低越好 | ≤ 5 | ≤ 10 |
| 周活跃用户数 | 越高越好 | 环比 ≥ -10% | ≥ -20% |

反馈六分类：计费问题、性能问题、体验问题、内容问题、功能缺失、其他。

## 五、数据安全与备份

- **数据只存在你这台电脑的浏览器里**（`localStorage`，键名 `ops-workbench-web-v1`），不会上传到任何服务器；
- 这意味着：换电脑、换浏览器、清浏览器数据 → 数据会没。**重要数据请定期点「导出工作区 JSON」备份**；
- 换设备时：新设备打开网页 → 数据页 → **导入工作区 JSON**；
- 想彻底清空：数据页 → **清空全部数据**。

> 注意与「自动采集」的区别：自动采集来的数据放在 `src\data\` 里，**会随网站一起公开**（仓库是 public 时任何人都能下载）。真实用户反馈、订单金额等敏感数据请先脱敏，或改用私有仓库部署。见 `docs\03-数据自动采集.md` 第九节。

## 六、AI 解读（可选）

「口径设置 → AI 解读」里可以填自己的 OpenAI 兼容接口（Base URL / API Key / 模型名）。
填了之后，各分析页会出现「生成解读」按钮，把**已经算好的事实**交给模型润色成一段话。

- 不填也完全可用，所有分析都是本地规则引擎算的；
- Key 只存在本机浏览器里，但**如果网页部署在公网，请不要在公用电脑上填 Key**；
- 页面会把你已算出的结论发给该接口，数据敏感时请自行判断。

## 七、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 导入后指标显示"未匹配" | 指标名称和口径表对不上。去「口径设置」加一条同名指标，或把 CSV 里的名称改成一致的 |
| 晨检说"没有数据" | 选的日期当天既没有日指标也没有反馈。换个日期，或去数据页导入 |
| 反馈全是"中性" | 反馈词表没覆盖到你们的说法。去「口径设置 → 反馈词表」补充关键词 |
| 整合分析里出现"无法判断" | 正常现象：说明指标和反馈对不上或数据缺失，页面会同时给出**补数清单** |
| 表格里 `—` | 缺数据或无法计算，不是 0 |
| 刷新页面数据没了 | 用的是 `file://` 打开且浏览器禁用了本地存储，改用 `scripts\serve.ps1` 或部署后的网址 |
| 顶栏显示「同步 未同步」 | 还没同步过。去「数据源」页点「立即同步」；本地 `file://` 打开时无法拉取数据，改用服务器 / 网址访问 |
| 顶栏显示「同步 异常」 | 拉不到 `manifest.json`。确认 `src\data\manifest.json` 存在、同步地址填对、线上已发布完；点「同步日志」看具体错误 |
| 「检查更新」说有文件待同步，但同步后没有新数据 | 文件不符合命名约定（`YYYY-MM-DD-metrics.csv` 等）会被忽略，见 `docs\03-数据自动采集.md` 第三节 |
| 浏览器控制台报 CORS 错误 | 同步地址指到了别的域名且对方没开 CORS。改用同站 `data/` |
